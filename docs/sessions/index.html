Managing sessions

Every conversation is a row in one SQLite file. Start one, resume one, clear one.

Commands

/clear
Start a fresh session. The old one stays on disk.
/resume
Pick a past session of this directory and continue it.
Ctrl+C ×2
Exit. Once aborts the running turn instead.
--db <path>
Point the whole session store somewhere else.

What a session carries

A session is not just messages. It keeps the provider and model pinned by /model, the agent chosen by /agent, and the permission grants answered with a. /resume restores all of it, so a resumed turn runs exactly like the one before it. It continues the session; it does not fork it.

Subagents are sessions too

A child launched by the subagent tool is a second session in the same store, linked to its parent. Children are hidden from /resume and the picker: only the child's final message returns to the parent.
