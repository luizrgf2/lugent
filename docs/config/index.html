Configuration

Providers, defaults and keys. The project file wins for providers; mcp, agents and skills merge both.

Where it reads from

For providers, defaultProvider, defaultModel and defaultAgent lugent reads the first file found: no merging.

lugent.json
Project root. Wins when present.
~/.config/lugent/config.json
Global fallback, works on Windows too.

mcp, agents and skills merge both files instead, the project winning per server or id.

Keys

Never inline a secret. Use {env:VAR} and lugent substitutes it at load time:

{ "apiKey": "{env:OPENROUTER_KEY}" }

Add a provider without editing the file

/add-provider is the alternative to writing the JSON above by hand. It opens a form — name, base URL, API key — and writes the global file only, leaving lugent.json alone. Every other key in that file survives.

Test
Calls <baseUrl>/models. Only a 200 with at least one model unlocks import; a failed test is recoverable — go back and edit a field instead of retyping the form.
Import
Writes the provider and every model id to providers.<name>.models, so /model lists it right away. An endpoint that answers with no models offers a models-less save, which keeps a list already cached.
Key
Stored exactly as typed — {env:VAR} stays a reference — and never printed back in either UI. A file holding an inline key is set to mode 0600.
Existing name
Never replaced silently: both UIs ask first, and say what is replaced (base URL, model list) and kept (the stored key, if the key field is left empty).

Defaults

defaultProvider
Provider a new session starts on.
defaultModel
Model for that provider.
defaultAgent
Startup agent. build when absent; an unknown id warns and falls back.
permissionMode
normal or yolo. A project value overrides the global one.
