# Prompt and agents

**Built-in agents.** `BUILTIN_AGENTS` (`build`, `plan`, `general`) is hardcoded in `agents.ts` and merged *before* the file scopes, so every install has all three and a file with the same id overrides one instead of removing it. `build.prompt` is `SYSTEM_PROMPT` itself — one source of truth, and the default prefix stays byte-identical (the golden snapshot keeps guarding it). `general` is a `mode: subagent` built-in (OpenCode's default delegate): full toolset, tool-default permissions, so the `subagent` tool has someone to launch in a clean install; being a built-in, it also means the default prefix now carries a one-entry `# Subagents` section. `resolveAgent(agents, id)` is the single resolution point: requested id if it exists, else `build` (what `defaultAgent` unset and an unknown id both land on); sessions store the resolved id, and a `null` agent (a session created before agents shipped) keeps the base prompt. New sessions therefore start on `build`, which is also the way back from `plan`.

**Identity and compatibility.** The agent **id** comes from the frontmatter `name`; the file's relative path (`team/x.md` → `team/x`) is only the fallback — so a nested `reviewer/agent.md` with `name: reviewer-2` loads as `reviewer-2`, and precedence compares the final id. Claude Code-style fields are translated at load, never dropped: `subagent: true` → `mode: subagent` (deprecation warning; explicit `mode` wins), `commandExecutionPolicy: off` → `permissions: {shell: deny}` unless the file declares `permissions.shell` itself, and `description` strips surrounding quotes (parity with `color`).

**Models are explicit or fatal.** `resolveChildModel` (spawn) walks the hierarchy: the agent's declared `model` → the config's `defaultSubagentModel` → the chat's current model. `agentActivationModel` (switch/startup/resume) resolves only the declared model. Both treat a declared model whose provider is not configured as **fatal**: `buildSpawn` stops before creating the child session (loop deps carry an `onFatal` seam; the CLI prints and exits), the plain REPL exits at the three activation points, and the TUI — which cannot die mid-picker — prints the error into the transcript and refuses the switch. Nothing ever runs on an unresolved model.

**Byte-stable prefix.** The system prompt is rebuilt from immutable inputs every iteration and pinned by a golden snapshot test. Identical bytes across requests let providers reuse their prompt cache — one changing line silently kills caching. A selected agent's prompt *replaces* the base prompt and gets its own pinned snapshot, so the prefix is byte-stable per agent; switching agent invalidates the cache once. The `# MCP` section sits *before* the agent prompt precisely because it must not be replaced: every agent, built-in or user-defined, receives it. It is unconditional so a user with no server configured can still ask how to add one (see `docs/decisions.md`).

**Subagents catalog.** The `# Subagents` section lists `id` + `description` for every `canBeSubagent` agent (mode `subagent` or `all`), right after `# Skills`. It renders only when the list is non-empty — since the `general` built-in it always carries that one entry in a clean install; a project that shadows `general` with a `mode: primary` file (or an agent that withheld the `subagent` tool) keeps it out. A child session's `PromptInput` sets `subagents: []`, so the section vanishes in the child and the depth-1 rule needs no code in the prompt itself (see `docs/decisions/agents.md`).
